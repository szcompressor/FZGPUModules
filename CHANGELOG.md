## [Unreleased] — 2.0.0

### Fixed
- `AdaptiveBitpackStage<T>::estimateScratchBytes()` was the inherited default `0`, but `execute()` (both forward and inverse) allocates two `uint32[num_blocks]` per-block arrays (`ab_cost`, `ab_offset`) plus the CUB `DeviceScan::ExclusiveSum` temp storage from the pool. Because `CompressionDAG::computeTopoPoolSize()` sums `estimateScratchBytes()` across stages to size the PREALLOCATE pool release-threshold (and the MINIMAL peak), this stage's scratch was invisible to per-stage memory accounting and the pool threshold was undersized by `~8·num_blocks + cub_temp` (the pipeline still ran — the CUDA async pool is not hard-capped — but reported memory was inaccurate and the release threshold could trigger spurious overflow). Now overridden to report the cost + offset arrays and the CUB temp (queried via `ExclusiveSum(nullptr, …)`), deriving the block count from the input bytes (forward) or the header element count (inverse). Brings the stage in line with the `RZEStage` precedent (the other CUB-scan coder, which already reports its scratch). The other recent cuSZp-family additions audited clean: `QuantizerStage` linear mode correctly no-ops its outlier-count scratch and reports `0` device footprint; `LorenzoStage::setBlockSize` and `TiledLorenzoStage` allocate no pool scratch (in-place predictors).
- `PipelinePerfResult::dag_elapsed_ms` was measuring kernel **launch/enqueue** time, not GPU execution. It was a host `steady_clock` delta around `dag_->execute()` (`compressor_exec.cpp`), but `execute()` ends in an async `cudaStreamWaitEvent` barrier (`dag.cpp`) and returns to the host *before* the GPU finishes — the blocking `cudaStreamSynchronize` happened after the end marker. So the headline device-time metric (and `throughput_gbs()`, the profiling tables, and the report throughput derived from it) understated compute and inflated throughput, with the error growing for fast pipelines. Now bracketed with a CUDA event pair via a new RAII `DagEventTimer` (`src/pipeline/dag_event_timer.h`), giving true device wall time from when the stream reaches the start marker until every kernel — including those joined back from internal streams at the end of `execute()` — has finished. Applied to all three execute paths: compress + in-memory decompress (`compressor_exec.cpp`) and `decompressFromFile` (`compressor_io.cpp`, previously a sum-of-levels estimate). Events are only created on the profiling path; without profiling `dag_elapsed_ms` falls back to the old host estimate for the log line only. Validated against `pfpl_manual_vs_dag`: the bracketed DAG time now sits between the sum-of-stage CUDA-event times (lower bound, excludes launch gaps) and host wall time (upper bound, includes setup). `perf.h` doc comment corrected to match.
- `modules/transforms/adm/adm_stage.cu` `ADMStage::initScratch` — undersized scratch allocations were causing 16-byte vector store OOBs in both the encode (`adm_map_decoupled_u16` / `adm_map_thrust_u16` / U32 variants) and decode (`adm_decompress_u16` / U32) kernels. The encode kernels each write a full `kBlockElems = 512` byte slice per grid block via vectorised `int4` stores, regardless of `num_elements`; the existing `d_codes_`, `d_concat_signals_`, `d_bit_signals_` allocations sized to `num_elements` (or `num_elements * sig_bytes`) were short by up to ~512 B when `num_elements` wasn't a multiple of 512. Pad to `gsize * kBlockElems` (only the first `num_elements` bytes are copied to user output). `modules/transforms/adm/mapping_uint{16,32}.cu` `adm_decompress_u{16,32}`: the early-out predicate `idx * kDecmpChunk > data_size` was off-by-one, letting the last partial-chunk thread fall through; combined with an unguarded vectorised int4 store this wrote past the user output buffer. Fixed predicate to `>=` and added a scalar tail loop for the last partial chunk. `test_adm` went from 63 → 0 sanitizer errors.
- `tests/pipeline/test_config.cpp` `round_trip_error()` and `tests/pipeline/test_ownership.cpp` (OW1, OW3 zero-size, OW6) — replicated the same pool-managed-pointer double-free the harness had: `cudaFree(d_dec)` on a pointer owned by `MemoryPool::graph_allocations_` (the Pipeline default since `pool_managed_decomp_=true`). Conditioned on `pipeline.isPoolManagedDecompOutput()`. The `DecompressDefaultCallerOwned` test now explicitly opts into caller-owned mode (via `setPoolManagedDecompOutput(false)`) to match its intent — the test name was inherited from when caller-owned was the default. `test_config` 11 → 0 errors, `test_ownership` 6 → 0 errors.
- `modules/coders/huffman/phf/hf_kernels.cu` `KERNEL_CUHIP_HF_decode` — guarded the post-symbol bit fetch in `single_thread_inflate`: after emitting a symbol the decoder unconditionally fetched the next bit, which when `total_bw % 32 == 0` triggered an `input[i / 32]` read one 32-bit word past the partition's bitstream slice (and past the encoded-bitstream allocation entirely on the final partition `gid == pardeg - 1`). compute-sanitizer flagged this as `Invalid __global__ read of size 4 bytes ... 1 byte after the nearest allocation` on every Huffman round-trip test where the last partition's bit count happened to land on a 32-bit boundary. Fix: only fetch when `i < total_bw`. The outer `while (i < total_bw)` catches the terminating case on the next iteration, so the fetch is unnecessary. `test_huffman` went from 91 → 0 sanitizer errors. Upstream PHF (origin/v1.1.0_dev) has the same bug; this fix lives in our adapter-deltas comment block.
- `tests/helpers/stage_harness.h` `pipeline_round_trip<T>()` was unconditionally calling `cudaFree(d_dec)` on the decompress output. When the pipeline uses `pool_managed_decomp_=true` (the default), `d_dec` is owned by `MemoryPool::graph_allocations_` and freed by `Pipeline::~Pipeline()` via `cudaFreeAsync`. The harness's extra `cudaFree` was a double-free that surfaced under compute-sanitizer as `cudaErrorInvalidValue` from `cudaFreeAsync` at teardown (one error per affected test), and the sticky error propagated to the next test's `cudaGetLastError()` checks in `CompressionDAG::addStage`. Harness now branches on `pipeline.isPoolManagedDecompOutput()` — only `cudaFree`s when the caller opted into caller-owned mode via `setPoolManagedDecompOutput(false)`. `pipeline_file_round_trip<T>()` unchanged (it uses the static `Pipeline::decompressFromFile`, which always returns a `cudaMalloc`-owned pointer). Also fixed two callers in `tests/stages/test_ginterp.cpp` (GI27, GI29) that replicated the same pattern inline. Result: `test_ginterp`, `test_lorenzo`, `test_quantizer`, `test_bitpack`, `test_ans`, `test_graph_capture` all report `ERROR SUMMARY: 0 errors` under `compute-sanitizer --tool=memcheck` (was 1+ pre-existing errors on most). `test_huffman` still has a pre-existing kernel-side issue unrelated to ownership.

### Changed
- `AdaptiveBitpackStage<T>` forward (compress) path is now **graph-compatible** (`isGraphCompatible()` returns `!is_inverse_`, was unconditional `false`). cuSZp's data-dependent compressed-size readback (`cmpSize` D2H + the `cudaStreamSynchronize` it required) was moved out of `execute()` into a new `postStreamSync()` override, which the pipeline calls after the launch and a full stream sync — outside any CUDA-graph capture window. To support reading the scanned payload length post-sync (and to avoid any allocation inside a captured graph replay), the per-block cost/offset arrays are now **persistent** pool scratch (`allocate(..., persistent=true)`, grown lazily when a larger input is seen, freed in the destructor) instead of per-execute alloc/free; the CUB scan temp stays transient. `execute()` sets a worst-case provisional `actual_output_size_` (graph *recording* does not invoke `postStreamSync`), which `postStreamSync()` then refines to `meta_region + scanned_payload`. Mirrors the `RZEStage` forward precedent. The inverse path is unchanged and remains out of graph capture. This makes the full modular cuSZp/cuSZp2/cuSZp3 compress pipelines (`Quantizer(linear) → Lorenzo(block)/TiledLorenzo → AdaptiveBitpack`) capturable and replayable as a CUDA graph. `tests/stages/test_adaptive_bitpack.cpp`: AB10 retargeted (`GraphCompatForwardOnly`) and new AB20 `GraphCaptureRoundTrip` (capture + 3× replay of the cuSZp compress graph, size-stability + within-bound round-trip); suite 20/20, compute-sanitizer clean. Docs: `docs/stages/adaptive_bitpack.md` graph-compatibility section.

- `TiledLorenzoStage<T>` (`modules/predictors/tiled_lorenzo/`, `StageType::TILED_LORENZO = 25`) — the cuSZp3 (SC'25) **dimension-aware (tiled separable) delta** predictor as a modular stage, completing the modular cuSZp3 pipeline. Within each fixed tile (default 8×8 in 2-D, 4×4×4 in 3-D; `setTileShape(tx,ty,tz)`, product ≤ 1024) it applies a separable integer Lorenzo — the leading x-column predicts down y (`prevQuant_y`), the leading y/z edges predict down z (`prevQuant_z`), and every other element predicts from its x neighbour — exactly mirroring the cuSZp3 plain/outlier kernels (verified against `compressors/cuSZp3/src/cuSZp_kernels_{2D,3D}_f32.cu`). The forward pass emits **tile-major** output (each tile's `tile_elems` elements contiguous, edge tiles zero-padded), so a downstream `AdaptiveBitpackStage(block_size = tile_elems)` packs each tile as exactly one block — reproducing cuSZp3's per-tile fixed-rate layout with the coder unchanged. The inverse un-tiles back to natural row-major order via a storage-free separable prefix-sum (3 running scalars per tile). Signed `int16_t`/`int32_t`; forward is parallel one-thread-per-output-element, inverse one-thread-per-tile (correctness-first; fusion is a downstream-compiler concern). Made a **separate stage** rather than a `LorenzoStage` mode because the tile-major reshape + padding break LorenzoStage's size/layout-preserving contract and the separable formula differs from its N-D inclusion-exclusion delta (same reasoning as `AdaptiveBitpackStage` vs `BitpackStage`). **Graph-compatible** (pure kernels, deterministic sizes; no D2H). **Independent reimplementation — no cuSZp source copied.** New 20-byte `TiledLorenzoConfig` (dtype, ndim, tile_x/y/z, dims) in the FZM header. Registered in `stage_factory.h`, `fzgpumodules.h`, and TOML (`type = "TiledLorenzo"`, `data_type`, `tile_x`/`tile_y`/`tile_z`). The three cuSZp3 modes map to: fixed = `Quantizer(linear) → AdaptiveBitpack`; plain = `… → TiledLorenzo → AdaptiveBitpack`; outlier = plain + `AdaptiveBitpack.setOutlierSelection(true)`. `tests/stages/test_tiled_lorenzo.cpp` — 14 tests (2-D/3-D int16/int32 round-trips, partial edge tiles in 2-D and 3-D, custom tile shape, constant field, `setTileShape` bounds, header round-trip, port/type/graph contract, stage-type id, the full `Quantizer(linear)→TiledLorenzo→AdaptiveBitpack(64)` plain and outlier float pipelines, and an FZM file round-trip); all pass, compute-sanitizer-clean (0 errors). Docs: `docs/stages/tiled_lorenzo.md`; design notes in `memory/cuszp_stages.md` Part 8.

- `AdaptiveBitpackStage<T>` (`modules/coders/adaptive_bitpack/`, `StageType::ADAPTIVE_BITPACK = 24`) — a per-block adaptive fixed-rate bit-plane coder: the cuSZp lossless back-end's "plain" mode as a modular stage. For each block of `setBlockSize(n)` signed elements (`int16_t`/`int32_t`; default n=32, range [1,1024]) it emits a rate byte (bit width of the block's largest magnitude) and, when non-zero, a sign bitmap + that many bit-planes (`ceil(n/8)` bytes each). Per-block payload offsets come from an ordinary CUB `DeviceScan::ExclusiveSum` over per-block byte costs — **not** cuSZp's fused decoupled look-back scan, which is a fusion-time lowering left to the downstream compiler. Single signed-codes input → single `uint8` archive (rate region + scan-packed payloads); `block_size`+`num_elements` live in the 16-byte FZM header (the archive needs no internal header). Kernels are one-thread-per-block for verifiability; **independent reimplementation — no cuSZp source copied** (THIRD_PARTY cuSZp section added). Not graph-compatible (forward D2H for the scanned length, like `BitplaneRLE`). Completes the modular cuSZp front-to-back pipeline `QuantizerStage(linear) → LorenzoStage(setBlockSize) → AdaptiveBitpackStage`. Also supports cuSZp2's per-block **outlier selection** via `setOutlierSelection(true)`: each block independently picks the cheaper of plain packing vs. extracting element 0 as a raw 1..`sizeof(T)`-byte outlier and packing only the rest (targets non-sparse data where the block-local predictor's first element is a full-magnitude delta-vs-0). Per-block metadata widens from 1 to 2 bytes (`[rate][sel]`) so the full `int32` rate range stays representable — cuSZp bit-packs the same flags into one byte; we keep them separate. The mode is carried in the FZM header. Registered in `stage_factory.h`, `fzgpumodules.h`, and TOML (`type = "AdaptiveBitpack"`, `input_type`, `block_size`, `outlier_selection`). `tests/stages/test_adaptive_bitpack.cpp` — 19 tests (int16/int32 round-trips, all-zero blocks, every fixed-rate 0–31, partial final block, INT_MIN/sign extremes, header round-trip, `setBlockSize` bounds, port/type contract, graph-compat=false, compression-ratio sanity, the full `Quantizer(linear)→Lorenzo(block=32)→AdaptiveBitpack` float pipeline, and outlier-mode round-trips covering every outlier byte-count, outlier-beats-plain, partial/single blocks, INT_MIN outlier, header flag, and the outlier-mode pipeline); all pass and compute-sanitizer-clean (0 errors). Docs: `docs/stages/adaptive_bitpack.md`; design notes in `memory/cuszp_stages.md` §7.3–7.4.
- `LorenzoStage::setBlockSize(uint32_t)` — an explicit, launch-decoupled 1-D block-local reset period (cuSZp-style; cuSZp uses 32). `n=0` (default) keeps the existing behavior (N-D inclusion-exclusion delta selected by `dims_`; the 1-D path already reset per 256-thread launch block). `n>0` forces the 1-D path over the flattened array and restarts the prediction chain every `n` elements regardless of launch config or `dims_`. - `QuantizerStage::setLinearMode(bool)` — a cuSZp-style linear / no-outlier quantization mode (ABS/NOA only). Maps each value to `q = round(x / (2·eb))` stored two's-complement in `TCode` with **no radius clamp, no outlier ports, no zigzag**; the forward kernel `quantizer_linear_fwd_kernel` is a pure memory-bound map (the regular forward kernel's only `atomicAdd` and only divergent branch — the outlier path — are removed), and the inverse reuses `quantizer_abs_inv_kernel<…,false>` with no memset/scatter. Single `"codes"` output (forward) / single input (inverse); the codes are *declared* as the signed DataType (`UINT16→INT16`, `UINT32→INT32`) so they connect directly to `LorenzoStage<intN>` — no new signed-`TCode` instantiations needed. Mutually exclusive with REL / inplace / zigzag — each throws at the first `compress()`. New `linear_mode` byte in `QuantizerConfig` (reuses former `_pad[0]`; struct size unchanged at 36 B, old headers default it to 0). Intended front-end for the modular cuSZp pipeline `Quantizer(linear) → LorenzoStage(blockSize=32) → AdaptiveBitpackStage` (see `memory/cuszp_stages.md` §7.1). `tests/stages/test_quantizer.cpp` — added QuantizerLinear suite (5 tests: ABS/NOA round-trips, port/type contract, header round-trip, incompatible-mode throws); full suite 34/34. - `BitplaneRLEStage` (`modules/fused/bitplane_rle/`, `StageType::BITPLANE_RLE = 23`) — the FZ-GPU lossless encoder, ported as a fused single-kernel stage. In one shared-memory pass per 4096-byte chunk it bit-transposes a 32×32 `uint32_t` matrix (a bitshuffle at 4-byte element width) and eliminates all-zero 4-byte groups, reserving each block's output slice with a global `atomicAdd`. Fixed `uint16_t` input (no template — matches the reference `using E = uint16_t`); single input → single `uint8_t` self-describing archive (128-byte header + bitflag bitmap + per-block start positions + compacted bitstream). The transpose is built in, so no `BitshuffleStage` goes in front of it; typical pipeline is `QuantizerStage<float,uint16_t> → BitplaneRLEStage`. Not graph-compatible (blocking D2H both directions: forward reads the compacted length to write the header, inverse reads the archive header). Inputs shorter than a 4096-byte multiple are zero-padded in a pool-allocated scratch buffer (and on decode, the kernel always writes the full padded length, so a non-aligned inverse decodes into a padded scratch and copies back only the original-length prefix — verified compute-sanitizer-clean, 8/8 tests, 0 errors); `original_len` is stored in the 8-byte FZM stage header so a cold decompress trims back. Functionally close to `Bitshuffle(ew=4) → RZE(levels=1)` but kept distinct for FZ-GPU fidelity (exact codec + archive) and throughput (transpose stays in shared memory — no global round-trip; zero-elim at 4-byte rather than per-byte granularity). Kernels adapted from `KERNEL_CUHIP_fz_fused_{encode,decode}` (Boyuan Zhang et al., HPDC '23) vendored in cuSZ `origin/v1.1.0_dev`; `namespace fzgpu` → `fz::bitplane_rle`, deps stripped, allocations routed through `MemoryPool`. Registered in `stage_factory.h`, `fzgpumodules.h`, and TOML config (`type = "BitplaneRLE"`, no tunable keys). `tests/stages/test_bitplane_rle.cpp` — 8 tests (patterned/non-aligned/dense/tiny round-trips, compression-ratio sanity, graph-compat=false, file round-trip via FZM header, and a `Quantizer→BitplaneRLE` float pipeline); full suite 31/31 pass. Docs: `docs/stages/bitplane_rle.md`; THIRD_PARTY entry added.
