## Issues found and addressed

- Fresh sanitizer workflows could build no tests, miss nested executables, or
  hide configure/UBSan failures. Presets and the runner now reject empty runs,
  propagate failures, and retain full diagnostics.
- Static installation omitted a private utility archive needed by exported
  static targets. The utility target is now installed and exported.
- ANS interpreted byte readback storage as a 32-byte-aligned header. Both host
  paths now copy into a correctly aligned object, preserving archive layout.
- Three quantizer fixtures passed null pointers to zero-length `memcpy` calls.
  They now skip empty copies.
- Huffman assembly read allocated bitstream capacity beyond the initialized
  prefix. It now copies populated lengths and checks capacities. Rationale:
  [CN-HFINIT-1](../codebase_notes.md#cn-hfinit-1--huffman-assembly-copies-populated-prefixes).
- Staged LorenzoQuant and Quantizer exposed unused outlier capacity to downstream
  Merge before count readback. They now initialize those advertised bytes on the
  execution stream. The new Quantizer→Merge regression covers both memory
  strategies and buffer reuse. This adds two stream-ordered clears and write
  traffic; no throughput neutrality is claimed. Runtime propagation of actual
  interior lengths remains separate work. Rationale:
  [CN-INIT-1](../codebase_notes.md#cn-init-1--defined-bytes-in-materialized-outlier-capacities).
- ANS coalescing left reserved header fields, metadata alignment slots, and
  partial payload vectors undefined. It now initializes those bytes and reads
  only valid encoded words. SZx and the quarantined SZp reference now initialize
  each byte before packing its first bit. Sizes and layouts are preserved;
  previously undefined padding bytes may change.
- An isolated inverse fixture used fresh AdaptiveBitpack stages without their
  serialized element counts, then compared unwritten outputs. It now restores
  metadata and checks logical length, bounds, and reference reconstruction. The
  `prepareInverse()` documentation distinguishes shape preparation from restoring
  metadata-bearing coders.

- Empty-input LorenzoQuant left cached outlier-count scratch uninitialized. It
  now clears existing scratch before returning, without allocating extra memory.
- GInterp mode-2 profiling reset and loaded shared samples without a barrier. An
  unconditional block barrier fixes the three reported warnings; all threads
  reach it. All 62 GInterp cases pass all four tools after the fix.

## Remaining review points

One full nonblocking racecheck attempt stalled in
`Concurrency.MultiSlot_RLE` for approximately five minutes and was explicitly
terminated. Its cause is unproven. The isolated normal nonblocking case later
passed in three seconds, and the entire six-case concurrency suite passed
racecheck in fifteen seconds. A serialized-launch diagnostic also passed, but
that diagnostic does not establish concurrent coverage. NVIDIA documents that
[forced blocking launches reduce error-reporting precision](https://docs.nvidia.com/compute-sanitizer/ComputeSanitizer/index.html#nonblocking-mode);
the final full concurrency rerun used normal nonblocking launches. The earlier
stall remains recorded rather than attributed to a confirmed tool or library bug.
The runner now fails bounded timeouts and retains their output.

The outlier-buffer clears add launch/write traffic; benchmark their demo impact
before claiming unchanged performance. A 4,096-element Huffman CLI fixture had
identical 3,584-byte compressed payloads before/after the copy-length fix; this
is one fixture, not a universal archive-identity claim. HIP, minimum-toolkit,
multi-GPU, and custom-context validation are outside this pass.

Logs and fresh builds are retained locally under
`/tmp/fzgm-v2-release-prep/`. Remote CI and publication remain pending; local
results do not stand in for a remote runner result.

## Additional release-scope audit

The stage review found that the broad stable-header promise exceeded the evidence
for CDF97, SPECK2D, wavelet correction, and SZx. The draft release notes and stage
pages now explicitly classify these paths as experimental. Implementations and
archive readers remain available. The review identified numerical limitations;
the sanitizer passes above are not a strict error-bound validation for every
floating-point input. See the [experimental scope](v2.0.0.md#experimental-modules).

## Python specialization demo follow-up

The adapter's `fzgpumodules:specialization = "auto"` selects library Pipeline
Specialization, but integer Lorenzo previously ignored `block_size`. This
prevented the manually constructed cuSZp-style chain from becoming block-local.
The local adapter patch now exposes/validates integer Lorenzo reset lengths,
rebuilds after changes, and reports forward/inverse group counts, implementation
names, and the forward fallback reason through `get_metrics()`.

`scripts/libpressio_specialization_demo.py` builds linear Quantizer → integer
Lorenzo → AdaptiveBitpack with matching 32-element blocks. On 262,147 synthetic
f32 values and ABS bound `2^-10`, Off installs zero groups; Auto installs one
`warp-register` forward and one `warp-register-inverse` inverse group. Both
return the original shape, maximum absolute error `2^-10`, and compression ratio
3.27139. One warmup per policy excludes pipeline construction/JIT from reported
repeated Python round-trip timing; this includes host/device transfers and does
not establish a general speedup or kernel-only throughput.

After this adapter change the C++ suite remains 56 passed / four expected legacy
skips, and the Python suite passes 34 assertions, including actual installation,
lazy inverse diagnostics, block-size readback, fallback after changing block size,
and host/device output checks. The complete Python suite also passes Compute
Sanitizer memcheck with zero errors. Library production code is unchanged from
the full sanitizer-tested build; no release has been created.

## Rehearsal and file ownership closure

The documented preflight → synthetic → full CLDHGH sequence passed from a fresh
shell. Actual specialization and accuracy match the runbook. CLDHGH Off/Auto
host-inclusive timings were close in this rehearsal; no general speedup claim
is made. Rehearsal logs remain in the dedicated demo environment.

The remaining CLI unrecognized-free warning was traced to duplicate result
ownership in static file decompression. The inverse DAG marks its result
persistent: reset preserves it, and DAG destruction owns its release. The file
helper freed it early, leaving the DAG's recorded pointer to be released again.
The pool rejected the duplicate attempt before CUDA, so memcheck alone missed
this ownership error. The helper now leaves the result to the DAG, clears its
compressed-blob pointer after release, and guards the separately allocated
caller output until copying/performance bookkeeping succeeds. See
[CN-FILEIO-1](../codebase_notes.md#cn-fileio-1--file-decode-result-has-one-owner).

The enhanced CLI regression failed before the fix on all three attempted decodes
and passes afterward, including repeated static decode without a perf result.
It checks reconstruction and captures diagnostics through DAG destruction.
An independent read-only review found no blocking issue.
