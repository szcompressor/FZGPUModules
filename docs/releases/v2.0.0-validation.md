# 2.0.0 stable-main validation

Release publication is pending joint review; no tag or release has been created.
The project remains version `2.0.0` and the changelog remains Unreleased.

## Catalog and evidence scope

Stable-main cleanup retains the validated CUDA production catalog, specialization,
installed-package support, and Python/libpressio integration capability. It removes
experimental modules, HIP configuration, research programs, artifacts, and demos.
See [branch policy](../branch_policy.md) and [release notes](v2.0.0.md).

The complete pre-split validation report, including sanitizer matrices,
experimental diagnostics, and Python demo results, is preserved on `development`.
Those historical results describe its larger catalog; they are not a substitute
for checking the cleaned stable-main package.

## Stable-main checks

Checked on 2026-10-13 with an H100 (SM 90), CUDA 12.9, and GCC 13.
Fresh Release and ASan/UBSan builds used `CMAKE_CUDA_ARCHITECTURES=native`.

- Release: all 55 registered test executables passed; supported examples built.
- ASan/UBSan: all 55 registered executables passed through the sanitizer wrapper.
  CUDA-compatible host settings disable leak detection; this does not establish
  host leak freedom.
- Installed consumer: a copied, relocated SDK passed separate archive write/read
  processes under Compute Sanitizer memcheck, with zero errors in each process.
  The configured source and build paths were temporarily hidden during execution.
  Both warp and chunk specializations passed Off/Auto payload identity,
  forward/inverse selection, and error bounds for aligned and partial inputs.
- Documentation/integration: all four checks passed (38 TOML examples/presets,
  104 note references, and 28 shipped stages); all seven checker fixture tests passed.
- `ENABLE_NVTX=ON` configured successfully and its memory-library target built.

Evidence logs are in `/tmp/fzgm-main-split*` on the validation host. The full
four-tool device sanitizer matrix remains historical development evidence;
the cleaned catalog was freshly checked with host sanitizers and the installed
specialization memcheck above. Jetstream A100 CI must validate the final pushed
revision before publication; these local results were obtained on an H100.

## Libpressio compatibility

The adapter is maintained separately in `/home/exouser/src/libpressio-fork`.
The checked stable-catalog adapter commit is `34acf24` on
`dev/fzgm-stable-sdk-20261013`.
It must be rebuilt against this smaller SDK; binaries that referenced removed
experimental stages are incompatible. Public-header probes omit unavailable stage
wrappers while preserving the `fzgpumodules:specialization` option and diagnostics.
The removed `fusion` option has no compatibility alias.

Against the cleaned installed SDK, 57 C++ tests passed and five unavailable-stage
tests skipped (three ADM cases, SZx, and legacy SZp). Python passed 36 checks and
explicitly skipped its SZx round trip. Targeted memcheck passed four tests with
zero errors: partial-input Off/Auto specialization, fresh-decoder behavior,
unavailable-stage rejection, and optional-stage metadata consistency. Logs are in
`/tmp/libpressio-fzgm-stable-compat`.

The frozen demonstration environment still uses its pre-split SDK; it is not
silently replaced by these validation builds. Demo instructions remain on
`development` in `docs/demos/python-specialization.md`.
